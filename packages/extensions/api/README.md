# Axl extension API

This package owns the public, presentation-only extension registrations used by Axl clients. Every registration returns a disposer. Extensions must declare each capability before activation.

The current surface is intentionally limited to terminal commands, shortcuts, status, working labels, widgets, event listeners, tool renderers, and bounded activities. It does not expose daemon or kernel internals.

`terminal.activities` registers client-local activities. Activities may declare a bounded minimum viewport. They receive structured keyboard and viewport-local mouse input, semantic frames, a bounded viewport, immutable safe status, immutable reduced-motion and text-only presentation preferences, coalesced invalidation, and a host-owned monotonic one-shot scheduler. Spans use semantic foreground styles and may independently request a generic semantic background: `surface`, `surfaceAlternate`, `accent`, `selection`, `success`, `warning`, or `error`. The client maps these roles through its active theme. Unknown roles fail contract validation. Clients without a matching presentation treatment preserve the text without a fill. Text-only clients omit background presentation while preserving span text. Activities must keep meaning available through text or other non-color cues. Mouse-aware activities opt in explicitly. Mouse input contains validated coordinates, button, phase, and modifiers, never terminal escape bytes or global layout coordinates. Activities that do not opt in retain ordinary terminal selection behavior. An activity may return `true` from `handleInput(...)` to consume an input that the host would otherwise handle. The terminal activity surface uses this generic result for local Escape actions before closing Lounge. Instance operations carry an epoch so input, preference reads, and callbacks from a suspended or replaced instance fail safely. Pause, resume, serialization, and disposal are explicit, and disposal is idempotent.

`terminal.activity-storage` adds an optional activity-scoped storage service. The host derives the namespace from the extension and activity IDs. Values must be bounded JSON data, and writes and resets use compare-and-swap revisions. Storage failures distinguish conflicts, invalid values, corruption, future versions, oversized data, permissions, lock contention, adapter unavailability, and aborts. The API exposes no paths, filesystem objects, daemon client, raw terminal output, unrestricted timers, or agent mutation methods.
